Pipeline

{% block pipeline_intro %}

Runs every hour on the hourly TNS file and once a day on the daily file plus every Follow-up object — as the DETECT daemon, and embedded in this site right after its own TNS import (same code, app/modules/DETECT). One run, seven steps:

{% endblock %}
    {% block pipeline_intake %}
  1. 1
    TNS ingest
    TNS reports land in transient.objects by an update-only-if-newer rule, whichever importer gets there first.
    details
    • DETECT's daemon and this site's hourly downloader both import; both follow the same contract: a field is only overwritten by a non-empty value, lastmodified never goes backwards, new objects get obj_id = kinder_id.
    • Full-column upsert keyed by name: coordinates, type, discovery mag & filter (by name, numeric TNS ids resolved), reporters, groups, last-modified.
    • New objects get obj_id = kinder_id; the discovery point is seeded into transient.photometry.
    • Snoozed objects wake up (→ Inbox) only when TNS's lastmodified is newer than what we hold; the wake-up is logged, and the review page says why the object is back.
    • Bulk path (COPY + UPDATE + INSERT) for backfills ≥ 5 000 rows.
  2. 2
    Targets
    The run's new TNS reports, and — daily — every object in Follow-up, so their light curves and M keep updating.
    3. {% endblock %}
  3. 3
    HEALPix cross-match
    Cone search in cat.desi (30″) and cat.lens (10″), 8–20 ms each.
    details
    • NESTED, NSIDE 8192 (26″ pixels); query_disc(inclusive) → B-tree on healpix_8192 → exact separation cut. Bounding-box fallback with 1/cos δ and RA wrap.
    • cat.desi: DESI DR1 (22.2 M, zcat_primary) + 22 k EDR-only targets (data_release='edr'), joined to LS DR10 Tractor shapes (R₅₀, e1/e2 → a, b, PA), WISE, stellar mass / SFR and AGN VACs. STAR spectra are kept aside as a “Star?” check.
    • cat.lens: Hsu, Karpenka and the merged lens catalogue.
  4. 4
    Host rule v1 · DLR
    d_DLR = offset from the galaxy centre in units of its own radius in that direction. Member if ≤ 4 (SER/DEV/COMP) or ≤ 8 (EXP/REX).
    details
    • Each candidate → a Tractor model: LS DR10 TAP match ≤ 3″ (direct) or ≤ 10″ (fallback), else the catalogue's own shape. R₅₀ floor 0.5″.
    • Tentative band up to 2× the limit; shreds merged when Δz ≤ 0.001 and one centre lies inside the other's R₂₅.
    • A model whose only spectrum is a QSO is a quasar, not a galaxy with outskirts: it hosts a transient only when nuclear (d_DLR ≤ 1), never tentatively.
    • A failed redshift fit (redrock ZWARN NODATA / POORDATA / …; 147 k rows carry the junk value z = 0.93275) is never a host; a small-Δχ² warning keeps the host but sends it to review (z-warn).
    • Host = the member with the smallest d_DLR; row preference DESI › Lens, GALAXY › QSO, direct › fallback, LS photometry › bare fibre, then nearest.
    • Runner-up within 1.5× → ambiguous; two spectra on one model with different z → z-conflict. Both keep the host but ask for a person.
    • Calibrated on 4 474 TNS-classified SNe with DESI hosts: completeness 92.5 % (86 % at z < 0.03, ≥ 95 % above z ≈ 0.06), wrong host 0.4 %, a host invented where none exists 6.7 %; the R₅₀ floor (0–2″) moves completeness by < 1 %.
    • A host chosen or rejected by a reviewer on this site is pinned and overrides the rule on later runs.
  5. 5
    Screening & score
    M = m − μ(z) − 2.5 log(1+z) − Aλ; known Galactic / AGN / classified objects sink, luminous, nuclear or too-bright ones rise.
    details
    • Planck 2018 flat ΛCDM (H₀ = 67.4, Ωm = 0.315), SFD98 × SF11 extinction — the same calculator.py everywhere.
    • m = the brightest real detection in the DB light curve (limits and mag 99 excluded), else the TNS discovery mag; both versions are stored.
    • z = the DESI host, else the TNS classification redshift.
    • Vetoes (score): Galactic −10 · AGN −10 · Classified −6 · Star? −3. Interest: host +3 (+2 if unclassified) · Luminous +3 · SLSN? +1 · TDE? +2 · Too-bright +3 · Lens +2 · glSN? +3 (+2 passive host) · Kilonova? +3.
    • Kilonova? = peak M > −17 and a post-peak decline ≥ 0.5 mag/day on the DB light curve (least-squares slope over the 10 days after the brightest detection, last point > 2σ fainter, limits ignored), nothing known against it; the g/r/i points are also counted against the POSSIS envelope (Coughlin+2020) as a consistency check.
  6. 6
    Image & upload
    LS DR10 cutout with the host ellipse, then everything into the Kinder DB.
    details
      {% block pipeline_upload %}
    • transient.cross_matches: one row per candidate, is_host, the rule's numbers in match_data.
    • transient.detect_screen: the verdict — host_status, score, tags, M (peak and discovery), z, d_DLR, offset.
    • transient.target_images: the finder; objects.tag: DETECT's tags (yours are left alone); objects.brightest_mag / brightest_abs_mag.
    • Object status is never touched by the pipeline.
      • {% endblock %}
  7. 7
    Review on Kinder
    A person reads the verdict, looks at the image, presses one key. Open the queue →

Host status

{{ host_badge('confirmed') }}
One galaxy contains the transient and nothing argues against it. Accept it with F or D.
{{ host_badge('review') }}
Ambiguous (a second galaxy nearly as close), conflicting z on the host, or the nearest galaxy is just outside the limit. Look, then set the host or say no.
{{ host_badge('none') }}
No spectroscopic galaxy contains it. Usually nothing to do.
